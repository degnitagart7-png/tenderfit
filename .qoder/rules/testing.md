# Правила тестирования

- Фреймворк: Vitest + React Testing Library (jsdom), конфигурация `vitest.config.ts`, setup `src/test/setup.ts`.
- Обязательны unit-тесты для: скоринга (веса, инверсия риска, hard blockers, правила вердикта, критический дедлайн), фильтрации/сортировки/пагинации, Zod-схем и валидации ИНН, парсеров ЕИС (parsePrice, parseRuDate, parseLaw, buildEisSearchUrl).
- Тесты домена пишутся на чистых функциях без моков React; время передаётся параметром, а не мокается глобально.
- Компонентные тесты: поведение, а не реализация (роль/текст → утверждение); минимум один тест «таблица меняется после фильтрации».
- Распределение вердиктов демо-базы проверяется скриптом `npx tsx scripts/check-distribution.ts`: ≥5 закупок в каждом из трёх вердиктов, ≥8 по 44-ФЗ, ≥8 по 223-ФЗ и ни одного нарушения правил `deriveVerdict`. Скрипт — гейт, а не справка: невыполнение даёт ненулевой код выхода. Точные количества вердиктов не фиксируются намеренно (пересмотр 01.10.2026): прежние числа были подобраны под демо-базу до перевзвешивания соответствия предмета, и осмысленная правка движка превращала проверку в ложный сбой. Проверяется инвариант — каждый вердикт представлен достаточным числом примеров и каждый выдан по правилу.
- Задача не считается выполненной, пока не проходят `npm run lint`, `npm run typecheck`, `npm test`, `npm run build` и `npx tsx scripts/check-distribution.ts`.
- Тесты не ходят в сеть. Реальный доступ к ЕИС проверяется вручную скриптом `scrape:eis`, а не в unit-тестах.
