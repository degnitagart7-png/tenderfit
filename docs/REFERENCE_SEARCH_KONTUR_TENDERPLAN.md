# Поиск в Контур.Закупках и Тендерплане: что именно копировать

Снято 22.09.2026 из живого кабинета zakupki.kontur.ru (пробный период, авторизация владельца) и с
публичной страницы tenderplan.ru (скриншоты продукта в разметке лендинга). Всё ниже — наблюдения
за интерфейсом, а не догадки; где поведение не проверялось, это помечено.

## Контур.Закупки: объём и состав индекса

Пустой поиск без фильтров отдаёт **108 253 288 закупок** и пишет «Анализ рынка за последние 2 года:
22.09.2024–22.09.2026». Типы торгов в фильтре: 44-ФЗ, 223-ФЗ, 615 ПП РФ, **Коммерческие**, Закупки
СНГ, Малые закупки. Коммерческие лежат в том же индексе и в той же выдаче, что и госзакупки: в первых
строках поиска по слову «вентиля» standen Bidzaar («Тендер № 365-169»), Росэлторг (ЕЭТП)
(«Запрос предложений № COM10092600057») и ЭТП «Фабрикант» («№ 5575401») — то есть у коммерческих
закупок своя нумерация площадки, а не извещение ЕИС, и часто нет НМЦ (цена показана прочерком).

Этапы: подача заявок, работа комиссии, завершены, планируются, отменены. «Планируются» — это
закупки из планов-графиков, то есть спрос, которого ещё нет в виде извещения.

## Панель фильтров Контур.Закупок (полный состав)

- **Ключевые слова** — плейсхолдер «Например: лыжи, лыжные палки, 36.40.11.133», то есть в одну
  строку пишут и слова, и коды ОКПД2. Рядом три переключателя: «Точное соответствие», «Исключать
  слова», **«Искать и по документам закупки»**.
- Регион поставки (все регионы / список).
- Этап (5 значений, см. выше).
- Тип торгов (6 значений).
- **Отрасль** — собственный рубрикатор Контура, двухуровневый, не ОКПД2. Верхние уровни, которые
  удалось снять: Безопасность; Бизнес, финансы, страхование; Деревообработка, лес; Информационные
  технологии, компьютеры, оборудование; Лёгкая промышленность; Ликвидация ЧС и гуманитарная помощь;
  Маркетинг, реклама, информационные услуги; далее список обрывается на «Сув…». Внутри — предметы,
  а не коды: «Системы видеонаблюдения: поставка, монтаж и обслуживание», «Разработка программного
  обеспечения», «Услуги в сфере информационной безопасности», «Компьютеры и комплектующие, оргтехника,
  оборудование для презентаций», «Расходные материалы», «Ремонт и техническое обслуживание».
  Есть «Выбрать все».
- Заказчик — токены «Добавить» / «Исключить» (ИНН или название); исключение заказчика — отдельный
  механизм, а не отсутствие в списке.
- Способ отбора, Площадка (списки не раскрывались).
- **Начальная цена** — диапазон, плюс два отдельных переключателя: «Включать закупки без НМЦ» и
  «Включать закупки в валюте». Без них диапазон молча отрезает все коммерческие закупки без цены и
  все валютные — у них НМЦ не сопоставима с рублёвым диапазоном.
- Авансирование: «С авансом по 44-ФЗ», «С авансом по 223-ФЗ», «Без аванса для других типов торгов».
- Обеспечение заявки / обеспечение контракта — диапазон плюс «Без обеспечения заявки/контракта».
- Преимущества и ограничения (по умолчанию «Не учитывать») — состав не раскрывался.
- Опубликовано — диапазон дат.
- Окончание подачи заявок — «Не учитывать / Сегодня / Меньше 2 дней / Меньше недели / Период».
- Кнопки: Найти, **Сохранить как шаблон**, **Умный поиск**, Сбросить поиск.

Состояние поиска живёт на сервере, а не в URL: адрес выдачи — `/grid/search?searchId=<uuid>`.
Ссылку на поиск нельзя передать как набор параметров, только как идентификатор сохранённого поиска.

## Что делает выдачу Контура точной

Запрос «вентиля» (неполное слово) нашёл **85 640 закупок**, и среди них «ВЕНТИЛЬ 15Б1БК ДУ20 РУ16»,
«деталей запорного органа вентиля», «Поставка баллонов БК-7-300Н и вентилей». Ни одна из этих строк
не содержит подстроку «вентиля» — значит работает поиск по основе слова, а не посимвольное
вхождение. Как именно устроена нормализация (стемминг или лемматизация), по интерфейсу не определить.

Под заголовком каждой закупки показан **сниппет из найденного**:
`... Закупка деталей запорного органа вентиля по чертежам ... Комплект деталей запорного органа вентиля 12.0103.00.000 ...`
— то есть совпадение ищется и подсвечивается не только в названии, но и в позициях спецификации и в
тексте документов. Это ровно то поле `сниппет`, которое заявлено в тарифе API «Поиск»
(см. `REFERENCE_KONTUR_API.md`).

Раскрывающиеся блоки в строке выдачи:

- **Место поставки**.
- **Объекты** — таблица спецификации: «Наименование» и «Количество»
  (`Комплект деталей запорного органа вентиля 12.0103.00.000 (согласно чертежей ам/кар-181) | 20,0 компл`).
  Позиции закупки — отдельная сущность, по ней идёт поиск.
- **Условия участия** — нормализованные короткие требования прямо в выдаче
  (в просмотренной строке: «Отсутствие участников в РНП») плюс ссылка «Подробные условия».
- **Участники и результаты** у завершённых закупок — кто участвовал и чем кончилось; у закупок без
  допущенных участников вместо этого «Протоколы». Рядом метки «Есть допущенный участник» /
  «Нет допущенных участников» / «Заключен договор» / «Победитель определен» / «Признана несостоявшейся».

Сортировки (весь список, снимается с выпадающего меню): **По дате публикации · Наиболее подходящие ·
По окончанию подачи заявок · По НМЦ · По дате планируемой публикации**. «Наиболее подходящие» —
по умолчанию. Из чего складывается эта пригодность, интерфейс не объясняет: ни процента, ни
расшифровки рядом с закупкой нет.

В строке выдачи есть срочность: «Осталось меньше 24 часов», «Осталось меньше 2 дней».

Отдельно — «Графики» и «Анализ рынка за последние 2 года» по текущему запросу, «Выгрузить в Excel»
и «Настроить выгрузку» (обе функции платные, в пробном периоде закрыты).

## «Умный поиск» Контура

Текст окна дословно: «Укажите ИНН организации, и умный поиск заполнит фильтры на основе вашей сферы
деятельности, участий в закупках и избранного. Функциональность доступна только после оплаты тарифа.»

То есть это не полнотекстовый AI-поиск, а **автозаполнение фильтров по профилю компании**: три
источника — сфера деятельности (ОКВЭД/отрасль), история участий в закупках, избранное. Результат —
готовый набор фильтров, который можно поправить и сохранить как шаблон. В пробном периоде функция
закрыта, поведение не проверялось.

В интерфейсе есть и онбординг-подсказка про ключевые слова: «Введите ключевые слова,
характеризующие ваш товар или услугу. Сервис подскажет, чем дополнить запрос» — то есть к запросу
предлагаются дополнительные слова. Сам список подсказок поймать не удалось: он появляется не при
наборе, а по другому событию.

## Тендерплан: поисковые «ключи» вместо одного запроса

Модель другая: поиск — это набор именованных **ключей**, каждый со своей конфигурацией и своим
счётчиком находок («Стулья офисные 45», «Оргтехника 157», «Мебель офисная 19», «Все 999+»). Ключ
настраивается один раз и дальше приносит новые закупки потоком.

Форма нового ключа (состав полей):

- «Выбрать по отрасли» и **«Экспертный режим»** — два способа задать тему.
- Название ключа.
- **«Поиск в названии контракта, номенклатуре»** — явный выбор области поиска.
- Ключевые слова / Исключая / **«Искать внутри документации»**.
- Округ и Регион (округ — уровень выше региона, в Контуре такого нет).
- **Классификатор ОКПД2** — отдельным полем, не вперемешку со словами.
- Закон: 44 ФЗ, 223 ФЗ, ПП РФ 615, **Коммерческие**.
- **План график** — поиск по планам-графикам как отдельный источник, а не только этап.
- Заказчик.
- Начальная цена от/до, размер обеспечения заявки, размер обеспечения контракта.
- Дата окончания.

Рядом с ключами — **«Метки»** («Участвуем», «Юристу», «Пропускаем») и «Ответственные»
(сотрудники), то есть ключи и метки образуют рабочий процесс команды, а не только фильтр.

## Тендерплан: аналитика по ключу — самая ценная находка

Блок «Анализ метки» по одному ключу («Оргтехника») показывает цифры, посчитанные по истории закупок,
подошедших под этот ключ:

| Показатель | Значение в снятом примере | Что означает |
| --- | --- | --- |
| Интересно | 157 | сколько закупок попало под ключ |
| Заказов на сумму | 136 млн ₽ | объём ниши |
| Актуальных | 71 на 42 млн ₽ | открытые сейчас |
| Завершённых | 33 на 12 млн ₽ | уже разыграно |
| План график | 53 на 82 млн ₽ | запланировано на будущее |
| **Процент допусков** | **79 %** | доля заявок, которые допустили к торгам |
| **Среднее количество поставщиков** | **4** | насколько плотная конкуренция |
| Ожидание результатов | 5 | торги идут |
| **Среднее снижение цены** | **18,7 %** (2,7 млн ₽) | сколько теряют в цене на торгах |
| **Требуют обеспечения** | **32 %** | доля закупок с обеспечением |

Отдельная таблица — по ответственным сотрудникам: всего, актуальных, завершённых, в исполнении,
процент побед, процент допусков. Плюс «Выручка по метке», выручка отслеживаемых конкурентов и
предполагаемая выручка.

Эти четыре показателя (допуски, число поставщиков, снижение цены, доля с обеспечением) — и есть
ответ на вопрос «хорошая ли закупка», причём посчитанный по истории, а не по тексту извещения.

## Тендерплан: карточка закупки в выдаче

В раскрытой строке видны поля, которых нет в нашей карточке:

- **Источник финансирования** («Федеральный бюджет»).
- **Сроки поставки** текстом («В течение 30 рабочих дней с даты заключения контракта»).
- **Упоминание об авансе** — не число, а признак с подсказкой: «Да, ознакомьтесь с документацией
  Проект контракта». То есть аванс они ищут по тексту документов и честно говорят, что он там
  упомянут, а не проставляют процент.
- **Преимущества** («СМП»).
- **Информация об объекте закупки** — позиции с кодом ОКПД2 и количеством
  (`Картридж для принтера Samsung SCX-3200 ... | 30.01.24.190 | 20.00 ШТ`).
- **Документы закупки** — список с датой и временем появления каждого файла
  («22.09.2026 в 09:20 ДЭА_Оргтехника_Комплектующие_ПК в сборе», «Изменения в ДЭА_22 06 2019»,
  «Извещение от 22.09.2026», «Техническое задание»). Время добавления документа — признак изменений
  в документации.
- Метка workflow («Участвуем»), способ размещения («Запрос котировок»), срок («Осталось 8 дней»),
  закон («44 ФЗ»), цена, обеспечения, заказчик.

## Где наше приложение отстаёт

Снято по коду на 22.09.2026.

1. **Поиск идёт по трём полям.** `filterRows` в `src/domain/filtering.ts` собирает строку
   `${tender.subject} ${tender.customerName} ${tender.regNumber}` и проверяет `includes(kw)`.
   Ни документов, ни позиций спецификации, ни ОКПД2 в поиске нет. При этом `buildTenderText` в
   `src/domain/scoring/index.ts` текст документов и требований уже собирает — то есть скоринг
   документацию читает, а поиск нет. Закупка «Оказание комплекса услуг по техническому обслуживанию
   инженерных систем» не найдётся по слову «вентиляция», хотя вся её спецификация — про вентиляцию.
2. **Совпадение посимвольное, не по основе слова.** «вентиля» у нас не найдёт «вентилятор» и
   «вентиль»; у Контура находит.
3. **Нет исключённых слов.** В домене есть `excludeKeywords` для синхронизации Контура
   (`REFERENCE_KONTUR_API.md`), но в фильтрах выдачи такого поля нет.
4. **Нет области поиска.** Нельзя сказать «ищи в номенклатуре» или «ищи внутри документации».
5. **Нет сниппета.** Мы не показываем, чем именно закупка подошла под запрос, — только вердикт.
6. **Нет рыночных сигналов.** Процент допусков, среднее число участников, среднее снижение цены и
   доля закупок с обеспечением у нас не считаются ни по ключу, ни по заказчику, хотя сырьё для них
   есть: завершённые закупки в базе и участники с признаком победы в выдаче тарифа «Поиск» Контура.
7. **Нет поиска по планам-графикам.** У нас только опубликованные извещения; «Планируются» Контура и
   «План график» Тендерплана — это спрос на месяцы вперёд.
8. **Условия участия не видны в списке.** У нас требования раскрываются только в карточке; Контур
   показывает нормализованные условия прямо в строке выдачи.
9. **Сортировка «Наиболее подходящие» у нас есть как `fitScore`, но она не объяснена** — правила
   `.qoder/rules/ux-legal.md` требуют объяснять каждый вердикт, а ранжирование списка сейчас
   объяснений не даёт.

## Что из этого доступно через API Контура

По презентации API (см. `REFERENCE_KONTUR_API.md`): тариф «Поиск» возвращает наименование, ИНН
заказчика и организатора, тип (ФЗ/коммерческая), способ отбора, номер на ЭТП, дату публикации,
ссылку на ЭТП, НМЦ, валюту, окончание подачи, места поставки, **сниппет**, а также участников с ИНН
и признаком «Победил» / «Подрядчик» / «Возможный участник». Документы и лоты — только в тарифе
«Получение закупок».

Отсюда прямое следствие для поиска: **сниппет и участники приходят из API, а позиции спецификации и
текст документов — нет**. Полнотекстовый поиск по документации на данных Контура возможен только
после дозагрузки карточек вторым тарифом, а вот рыночные сигналы (число участников, победитель,
снижение цены) собираются из первого тарифа по завершённым закупкам.

Проверить это на живом ключе больше не нужно: состав полей запроса описан спецификацией OpenAPI
3.0.4 «АПИ Закупок» (разбор — `REFERENCE_KONTUR_API.md`). ОКПД2 поисковый запрос **не принимает**
ни отдельным полем, ни внутри строки ключевых слов как фильтр; вместо него у Контура свой отраслевой
рубрикатор `Categories` / `CategoryIds` (64 значения: «20 — Строительные работы», «21 —
Проектирование» и т. д.), а соответствие ему наших кодов ничем не подтверждено. «Искать по
документам» — флаг `Attachments` в теле запроса, он подключён. Сниппет приходит полем `Snippets`
записи выдачи и доступен как модификатор тарифа группы `search`; участники — полем `Participants`,
а фильтр по ИНН участников (`ParticipantsInns`) требует тариф «Поиск 2.0».
