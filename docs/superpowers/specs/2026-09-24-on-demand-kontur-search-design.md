# Кнопка «Найти новые закупки»: прогон по требованию через Контур.Закупки

Дата: 2026-09-24. Статус: реализовано и выложено на прод 2026-09-24, живой прогон
выполнен (см. «Итог проверки»).

## Проблема

Кнопка «Найти новые закупки» на дашборде (`DashboardView.tsx:190`) зовёт `useTenderData.sync()`,
который по каждому включённому профилю поиска обращается к `POST /api/tenders/sync`. Этот роут
поднимает адаптер ЕИС внутри серверлесс-функции Vercel, а ЕИС и Сбербанк-АСТ не отвечают
зарубежным IP. На проде кнопка не работает никогда: пользователь видит карточку
«Новые закупки не загрузились», а пустое состояние обещает поиск в трёх источниках.

Единственный прогон, который действительно наполняет ленту, — локальный `scripts/sync-eis.ts`
по расписанию Windows Task Scheduler раз в 2 часа (задача «TenderFit EIS Sync», минута :54).
Он работает, потому что выходит в сеть с российского IP владельца.

Живой поиск нужен по нажатию, а не по расписанию.

## Ограничение, которое определяет решение

С сервера Vercel доступен только платный источник Контур.Закупки. Проверено на проде
2026-09-24 после добавления `KONTUR_API_KEY` в Production: `GET /api/kontur/usage` отвечает
`configured: true`, `tariffError: null`, остаток по группе `search` 24 из 30,
подписка до 2026-09-30T18:59Z. Косвенное подтверждение платного поиска с зарубежного выхода —
прогон 24.09 20:54 с IP 2.26.131.126: Контур отдал 30 закупок, ЕИС и Сбербанк не ответили.

Отсюда три следствия, которые владелец принял:

1. Кнопка ищет только в Контур.Закупках и тратит платный бюджет: каждое ключевое слово —
   один платный поиск, 30 поисков в сутки на тариф.
2. Плановый локальный прогон раз в 2 часа остаётся: только он приносит ЕИС и Сбербанк-АСТ
   (144 из 166 строк ленты на 24.09) и только он качает документацию для глубокого анализа —
   поисковая выдача Контур не содержит списка файлов (`Docs` пуст, файлы приходят лишь
   в платной карточке), а filestore ЕИС с Vercel недоступен.
3. Кнопка не заменяет прогон, а дополняет его: мгновенно добавляет свежие закупки
   платного источника между прогонами.

## Поведение кнопки

Одно нажатие = один профиль поиска = не больше 3 платных поисков.

- Нажатие открывает панель подтверждения, а не запускает прогон сразу: расход платный,
  и он обязан быть виден до, а не после.
- В панели: выбор профиля (если включённых больше одного), строка
  «Потратит до 3 платных поисков · остаток 24 из 30», кнопка «Запустить».
- Остаток берётся из `GET /api/kontur/usage` в момент открытия панели. Вызов бесплатный
  (`/external/v1/limitGroups` не списывает лимит), но на каждой загрузке страницы
  дёргать его не нужно.
- Если в профиле больше трёх ключевых слов, в поиск уходят первые три, а панель честно
  сообщает, сколько слов осталось за бортом.
- После прогона — отчёт со счётчиками из ответа роута: найдено, сохранено, уже было
  от другого источника, потрачено поисков, остаток по тарифу. Затем лента перечитывается.

Правило «не больше трёх» живёт в одной чистой функции `konturPressPlan`
(`src/domain/konturPressPlan.ts`), а не размазано по компоненту: его можно проверить
тестом без сети и нельзя случайно обойти при правке вёрстки. Серверная защита от перерасхода
остаётся прежней и не зависит от клиента: адаптер проверяет остаток тарифа до платного
запроса и держит суточный бюджет `KONTUR_DAILY_REQUEST_LIMIT`, при исчерпании — 429.

Потолок пришлось ставить дважды. Трёх ключевых слов мало: `fetchTenders` листает выдачу,
пока не наберётся `limit` **подходящих** записей (регион и ОКПД2 отсеиваются локально),
а каждая страница по 50 записей — отдельный платный поиск, `maxPages` по умолчанию 5.
Профиль с фильтром региона превратил бы обещанные три поиска в пятнадцать. Поэтому хук
присылает `maxPages: 1`, роут принимает это поле и зажимает его в
`[1, KONTUR_MAX_PAGES_DEFAULT]`, а константа экспортирована из адаптера, чтобы роут и
адаптер не разъехались. Показанная цена совпадает с фактическим расходом; плата за потолок —
не больше 50 записей на слово. Повторное нажатие с теми же словами и фильтрами в пределах
TTL кэша (`KONTUR_CACHE_TTL_SEARCH_SEC`, сутки) берётся из `kontur_raw_responses` бесплатно.

## Чего кнопка не делает

- Не удаляет строки, выпавшие из выдачи источника: очистка ленты остаётся за плановым
  прогоном. Кнопка только дописывает и обновляет строки, поэтому она не может проредить ленту.
- Не перезаписывает закупки более авторитетного источника (`TENDER_SOURCE_PRIORITY`):
  такие попадания считаются в `duplicates`.
- Не качает документацию и не запускает глубокий анализ.
- Не обращается к ЕИС и Сбербанк-АСТ.

## Тексты

Пустое состояние дашборда больше не обещает три источника: «„Найти новые закупки“ ищет
в Контур.Закупках сразу; ЕИС и Сбербанк-АСТ добавляет плановый прогон на вашем компьютере
раз в 2 часа». Тот же текст — в панели до запуска, рядом с ценой.

Из карточки сбоя убран совет «Проверьте подключение к интернету или попробуйте позже»:
401, 429 и 503 приходят с сервера и к соединению пользователя отношения не имеют, а текст
ошибки роута печатается как есть. Сетевой сбой на стороне браузера (`TypeError`) отличим
от ответа сервера и даёт свою фразу — «Сервер не ответил — проверьте подключение к интернету
и попробуйте снова». `lastSynced` при сбое не обнуляется: время последнего удачного прогона
остаётся правдой.

При `configured: false` вместо кнопки — «Сервер не может опросить Контур.Закупки: ключ
источника не задан». При 429 — фраза роута про исчерпанный суточный бюджет. При 401 —
что ключ отклонён. При 502 — что ответ источника не похож на JSON.

## Проверка

Локально: `npm run lint`, `npm run typecheck`, `npm test`, `npm run build`,
`npx tsx scripts/check-distribution.ts` — по текущему дереву непосредственно перед деплоем
(дерево правят несколько сессий одновременно).

На проде после деплоя: `GET /api/kontur/usage` → `configured: true` и остаток по группе
`search`; одно реальное нажатие кнопки — 3 платных поиска, в отчёте ненулевое `synced`,
в базе рост строк `data_source='KONTUR'`, в журнале `spentTodayByMethod.search` +3.
Проверка прода идёт через `curl -sk --resolve tenderfit-ai-sage.vercel.app:443:76.76.21.21`,
потому что российский выход провайдера подменяет DNS `*.vercel.app`.

## Итог проверки

Локально 2026-09-24 по текущему дереву: lint чисто, typecheck чисто, 1212 тестов в 63 файлах
зелёные, сборка проходит, `scripts/check-distribution.ts` — все требования ТЗ `true`
(35 закупок: 9 RECOMMENDED, 8 MANUAL_REVIEW, 18 NOT_RECOMMENDED).

Прод после деплоя `tenderfit-12bkfeot7-degnis-projects.vercel.app` (алиас
`tenderfit-ai-sage.vercel.app`). До прогона: `configured: true`, `tariffError: null`,
группа `search` 24 из 30, подписка до 2026-09-30T18:59Z.

Одно нажатие кнопки — тело запроса ровно то, что собирает `syncKontur` для первого
демо-профиля (законы 44-ФЗ и 223-ФЗ, слова «компьютер», «ноутбук», «принтер»,
`maxPages: 1`, `limit: 50`, `saveDocuments: false`): HTTP 200 за 31,6 с,
`apiCalls: 3`, `searches: 3`, `synced: 72`, `created: 64`, `updated: 4`, `duplicates: 4`,
`filteredOut: 76`, `skipped: ['abandoned']`, `errors: []`, `availableRequests: 21`.
Прочитано 150 записей = 3 слова × 1 страница, значит потолок в одну страницу работает:
без него адаптер листал бы выдачу до пяти страниц на слово. После прогона группа `search`
21 из 30, `spentTodayByMethod.search` 9 (было 6) — ровно +3.

База: 230 строк, из них `KONTUR` 86 (64 добавлены этим нажатием), `EIS` 108, `SBER_AST` 36.
У 49 из 64 новых закупок нет НМЦ — это штатно: `MaxPriceNone` по умолчанию `true`,
такие закупки показываются с пометкой.

Повторное нажатие через 12 минут с тем же телом: HTTP 200, `apiCalls: 0`, `cacheHits: 3`,
`availableRequests` и `requestsToday` не изменились, `synced: 72`, `created: 0`,
`updated: 68`. Обещание «повторный поиск берётся из кэша и бюджет не расходует»
подтверждено живым прогоном.

Побочно найденное и исправленное в ходе проверки: счётчик `cacheHits` в адаптере считал
попадания в кэш по всем видам запросов, включая бесплатный `/limitGroups`, а показывался
рядом с числом платных. Первый прогон напечатал бы партнёру «платных поисков 3 · из кэша 3»
при трёх реально списанных поисках. Теперь считаются только платные виды — как в суточной
сводке `konturCacheRepository.summaryToday`. Регрессия закреплена тестом
«остаток кэшируется на пять минут, а force читает у источника».

Клиентская часть проверена в собранном виде: в развёрнутом чанке
`/_next/static/chunks/app/(app)/dashboard/page-59ba9c4cf5959f0f.js` найдены строки панели
(«Поиск в Контур.Закупках», «Потратит до … платных поисков», «Потратит 1 платный поиск»,
«Прогон платный», «ключ источника не задан», «Документации у новых закупок нет»,
`tender-search-panel`) и сообщения хука («Нет включённого профиля поиска»,
«Сервер не ответил»). В браузере панель не открывали: `*.vercel.app` с российского выхода
не резолвится, а правка hosts ради проверки — изменение системы, на которое спроса не было.
