# Референс: публичный каталог tender-ai.tech/public-tenders

> Осмотр 21.09.2026. Цель документа — зафиксировать рабочую модель публичного каталога
> тендеров, которую берём за основу для «ТендерФит AI». Это конкурент/референс, не наш код.
> Позиционирование, лендинг и страница доверия разобраны отдельно в [REFERENCE_COMPETITORS.md](./REFERENCE_COMPETITORS.md).

## Что это за страница

Публичная SEO-витрина живых госзакупок: поиск по названию, лента карточек с пагинацией,
счётчики объёма базы и конверсионные блоки на регистрацию («AI-анализ бесплатно»).
Внутри личного кабинета у них отдельный функционал; нас интересует именно витрина.

## Технический контур (фактически observed)

- Next.js, данные ленты подгружаются на клиенте после рендера (первый снапшот показывает «0 найдено», затем лента наполняется).
- Бэкенд — Supabase PostgREST, спрятанный за прокси `/api/sb/rest/v1/...`. Прямой запрос к таблице без заголовка ключа возвращает 401 → ключ инъектится на сервере, в браузер не уходит. Это правильный паттерн безопасности, повторяем его.
- Таблицы:
  - `tenders_live`: `id, title, customer, budget, region, deadline, platform, platform_url, category, external_id, created_at, status`.
  - `app_settings`: пары key/value, в т.ч. `feed_active_total` (красивый счётчик «83 546+») и `feed_active_total_updated_at`.
  - `blog_posts`: SEO-блог (`slug, title, status=published, published_at`).
- Запрос ленты: `status=eq.active & order=created_at.desc & offset=0 & limit=30` → серверная пагинация offset/limit, по 30 карточек на страницу.
- База обновляется каждый час (заявлено в подзаголовке); счётчик объёма хранится в `app_settings`, а не считается на клиенте.
- Аналитика — Яндекс.Метрика.

## Функциональный слой витрины

Карточка тендера (состав полей, сверху вниз):

1. Название — ссылка на детальную `/tender/{uuid}`.
2. Заказчик (обрезается по длине).
3. Регион.
4. Срок «До дд.мм.гггг».
5. Категорийный чип (Промышленность, IT и телекоммуникации и т.п.).
6. Чип «N дн.» — сколько осталось до дедлайна.
7. Справа — бюджет в человекочитаемом виде («1.4 млн ₽», «800 тыс ₽»).
8. Кнопка «AI-анализ» — гейт-CTA: без входа ничего не открывает, ведёт в регистрацию.

Вокруг ленты:

- Hero с H1 «Актуальные тендеры России», SEO-подзаголовком (регионы, категории, бюджет, 44-ФЗ/223-ФЗ) и тремя счётчиками-пиллами (найдено тендеров / регионов / 24/7 мониторинг).
- Поиск по названию (единственный фильтр на странице; региона/бююджета/закона в UI витрины нет — они живут на посадочных и в кабинете).
- Пагинация номерами + строка «Страница 1 из 2 835. Всего 83 546 тендеров».
- Конверсионные вставки: зелёный баннер «Бесплатный AI-анализ каждый день», три фиче-карточки (AI-анализ / Умные фильтры / Уведомления), повторный CTA-блок перед футером.
- SEO-хаб: блок «Каталог актуальных тендеров и госзакупок России» с четырьмя сильными посадочными (44-ФЗ, 223-ФЗ, мониторинг, анализ документации) + в футере хабы по регионам и ОКПД2. Осознанная стратегия: несколько сильных страниц вместо тысяч тонких.
- Хлебные крошки, футер с реквизитами ИП и контактами.

## Что берём на вооружение (сопоставление с нашей архитектурой)

| Элемент референса | Наша реализация |
| --- | --- |
| Прокси к Supabase с серверной инъекцией ключа | Наш API-роут `/api/tenders` (Next.js), ключ только на сервере; клиент ходит в свой роут, не в PostgREST |
| Таблица `tenders_live` + `status=active` | Та же схема полей; наполнение — почасовой джоб на базе уже рабочего `EisTenderSourceAdapter` (см. ACCESS_EIS.md) |
| Счётчик объёма в `app_settings` | Храним агрегат рядом с лентой, обновляет джоб; не считаем на клиенте |
| Серверная пагинация offset/limit, 30/страница | Повторяем; у нас уже есть чистая пагинация в `domain/filtering.ts` — переиспользовать |
| Состав полей карточки (название/заказчик/регион/срок/категория/дней/бюджет) | Берём как есть; форматирование через `src/utils/format.ts` (₽, дд.мм.гггг) |
| Чип «N дн.» и красный критический срок | У нас уже есть правило «< 24 ч — красным» (ux-legal) — совпадает |
| Кнопка «AI-анализ» как гейт на регистрацию | У нас анализ настоящий (детерминированный скоринг) — это наше преимущество; гейт оставляем, но ведёт в онбординг, после которого анализ реально работает |
| SEO-хабы (44-ФЗ / 223-ФЗ / мониторинг / анализ документации, регионы, ОКПД2) | Повторяем стратегию «несколько сильных страниц»; у нас под это уже есть фильтры по законам/регионам/ОКПД2 в `TenderFiltersPanel` |
| Поиск по названию на витрине | Добавляем; наши расширенные фильтры оставляем в кабинете, на витрине — лёгкий набор |

## Что НЕ копируем

- Пустую кнопку «AI-анализ» без входа: у них это заглушка-воронка, у нас анализ должен работать сразу после онбординга (иначе нарушаем собственное правило «каждый вердикт объяснён»).
- Отдельную клиентскую загрузку ленты с миганием «0 найдено»: нашу витрину рендерим на сервере (SSR) — быстрее и лучше для SEO; клиентом только пагинация/поиск.
- Хранение персональных данных кабинета в Supabase без необходимости: кабинет пока остаётся на localStorage (см. ARCHITECTURE.md), в серверную БД уходит только публичный фид.

## Порядок внедрения (черновик, см. ROADMAP.md)

1. Схема Supabase: `tenders_live`, `app_settings`; прокси-роут `/api/tenders` (list + count), ключ на сервере.
2. Почасовой джоб обновления: `EisTenderSourceAdapter` → нормализация → upsert в `tenders_live` + пересчёт `feed_active_total`.
3. Публичная страница `/public-tenders`: SSR-лента, поиск по названию, пагинация, карточка по составу выше, CTA-блоки.
4. Детальная `/tender/[id]` из `tenders_live` + кнопка «AI-анализ» → онбординг/кабинет.
5. SEO-хабы 44-ФЗ / 223-ФЗ / мониторинг / анализ документации + регионы и ОКПД2 (переиспользуют тот же list-эндпоинт с фильтрами).
